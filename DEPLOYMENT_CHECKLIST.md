# Pre-Deployment Checklist

Use this checklist before deploying to Render to ensure everything is ready.

## ✅ Required Files

- [x] `render.yaml` - Render blueprint configuration
- [x] `backend/requirements.txt` - Python dependencies (includes PostgreSQL support)
- [x] `backend/main.py` - Backend entry point
- [x] `frontend/package.json` - Node.js dependencies
- [x] `frontend/vite.config.ts` - Vite configuration
- [x] `DEPLOYMENT.md` - Deployment guide
- [x] `LOCAL_SETUP.md` - Local development guide

## ✅ Backend Configuration

- [x] PostgreSQL drivers added (`psycopg2-binary`, `asyncpg`)
- [x] Config supports both SQLite (local) and PostgreSQL (production)
- [x] Database service handles async PostgreSQL connections
- [x] CORS configured to accept frontend requests
- [x] Health check endpoint exists at `/health`
- [x] Build command: `pip install -r backend/requirements.txt`
- [x] Start command: `cd backend && uvicorn main:app --host 0.0.0.0 --port $PORT`

## ✅ Frontend Configuration

- [x] Build command configured: `cd frontend && npm install && npm run build`
- [x] Static files published from `./frontend/dist`
- [x] Environment variable `VITE_API_BASE_URL` points to backend
- [x] Routing configured for SPA (all routes → index.html)

## ✅ Database Configuration

- [x] PostgreSQL database defined in `render.yaml`
- [x] Database name: `warhammer_rankings`
- [x] Auto-connection from backend service
- [x] Tables auto-created on first run

## ✅ Environment Variables

### Auto-Configured
- [x] `DATABASE_URL` - From PostgreSQL service
- [x] `SECRET_KEY` - Auto-generated by Render
- [x] `PORT` - Assigned by Render
- [x] `API_HOST` - Set to 0.0.0.0
- [x] `ENVIRONMENT` - Set to production
- [x] `CORS_ORIGINS` - Configured

### Optional (Add Manually in Render Dashboard)
- [ ] `DISCORD_TOKEN` - If using Discord integration
- [ ] `DISCORD_GUILD_ID` - If using Discord integration

## 📝 Before Deploying

1. **Commit all changes**
   ```bash
   git add .
   git commit -m "Configure for Render deployment"
   git push origin main
   ```

2. **Verify your repository**
   - [ ] All files pushed to GitHub
   - [ ] Repository is public or Render has access
   - [ ] `render.yaml` is in the root directory

3. **Review service names**
   - Backend: `warhammer-ranking-api`
   - Frontend: `warhammer-ranking-frontend`
   - Database: `warhammer-ranking-db`

## 🚀 Deployment Steps

1. [ ] Go to https://dashboard.render.com
2. [ ] Click **New** → **Blueprint**
3. [ ] Connect your GitHub repository
4. [ ] Wait for Render to detect `render.yaml`
5. [ ] Review the services to be created
6. [ ] Click **Apply** to start deployment
7. [ ] Wait for services to build (~5-10 minutes)
8. [ ] Verify deployment at the provided URLs

## ✅ Post-Deployment Verification

1. [ ] Backend API is accessible
   - URL: `https://warhammer-ranking-api.onrender.com`
   - Check: `https://warhammer-ranking-api.onrender.com/health`
   - Docs: `https://warhammer-ranking-api.onrender.com/docs`

2. [ ] Frontend loads correctly
   - URL: `https://warhammer-ranking-frontend.onrender.com`
   - Check: Can you see the homepage?

3. [ ] Frontend can connect to backend
   - Try creating a game or viewing rankings
   - Check browser console for errors

4. [ ] Database is working
   - Create a test game
   - Add a test player
   - Record a test match
   - Verify data persists

## 🔧 Troubleshooting

### Backend won't start
- [ ] Check logs in Render Dashboard
- [ ] Verify `DATABASE_URL` is set correctly
- [ ] Check Python version compatibility

### Frontend shows errors
- [ ] Verify `VITE_API_BASE_URL` is correct
- [ ] Check CORS configuration in backend
- [ ] Look at browser console for errors

### Database connection fails
- [ ] Verify PostgreSQL database is running
- [ ] Check connection string format
- [ ] Review database logs
